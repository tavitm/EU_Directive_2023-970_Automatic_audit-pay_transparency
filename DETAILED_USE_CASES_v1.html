Step-by-step workflows for EU Directive 2023/970 compliance implementation

⚙️UC1: Job Evaluation Setup & Methodology Definition

Actor(s) Compliance Officer, HR Specialist
Trigger System initialization or methodology update
Duration 15-30 minutes
Directive Reference Art. 4 (Job Evaluation Criteria)

Narrative Description

The Compliance Officer establishes the organization's job evaluation methodology to ensure objective, non-discriminatory assessment of job value. This foundational workflow defines the criteria and weighting that will be applied across all salary gap analysis activities.

Pre-conditions

  • User has "Compliance Officer" or "HR Specialist" role with Job Management permissions
  • System has been initialized and is in operational state
  • Organization has not yet defined evaluation criteria (first-time setup)

Main Flow

1
Open Job Evaluation Methodology Interface
Compliance Officer navigates to Administration → Job Management → Evaluation Criteria. System displays the Job Evaluation form with default criteria template.
2
Review Default Criteria Framework
System presents the 7 standard job evaluation criteria: Competencies (25%), Effort (15%), Responsibility (25%), Working Conditions (10%), Complexity (10%), Autonomy (10%), Impact on Organization (5%). Officer reviews these criteria and their weighting.
Decision Point: Does the organization want to use default criteria or customize them?
3A
[If Using Defaults] Confirm Criteria
Officer clicks "Use Default Criteria". System validates that weights total 100% and displays confirmation dialog: "These criteria will apply to all 1,234 existing jobs and future positions."
3B
[If Customizing] Edit Criteria Weights
Officer clicks "Customize". Form becomes editable. Officer adjusts weights for each criterion. System provides real-time validation: "Total weight is 98% (must equal 100%)" displayed in red warning box. Officer adjusts until total equals 100%.
4
Define Scoring Scales
For each criterion, officer defines scoring scale (1-5 points). Example: Competencies: 1=Basic, 2=Intermediate, 3=Proficient, 4=Advanced, 5=Expert. System allows predefined scales or custom definitions.
5
Add Justification Guidelines
Officer enters guidance text for evaluators explaining how to assess each criterion. Example for "Responsibility": "Consider scope of decisions, budget authority, team leadership, and impact on business outcomes."
6
Set Approval & Activation
Officer selects "Activate Methodology". System displays confirmation: "This methodology will apply to all new job evaluations. Existing evaluations remain unchanged unless manually recalculated."
7
System Audit Logging
System records: User ID (pseudonymized), Timestamp, Action ("Methodology Activated"), Criteria Weights (encrypted), IP Address, Change Summary. Entry added to immutable audit trail.
✓ Success Outcome: Job evaluation methodology is now active. Compliance Officer receives confirmation email. System is ready for job evaluation workflow (UC2 prerequisite).

Alternative Flows

A1
Methodology Update After Activation
If officer clicks "Update Active Methodology", system displays: "1,234 jobs currently evaluated with v1 methodology. New jobs will use updated criteria. Update 1,234 existing evaluations?" Officer can choose to update all (30-min batch job) or apply new methodology to new jobs only.
A2
Save as Draft
Officer clicks "Save as Draft" without activating. Methodology is saved but not applied. System shows "Status: Draft" badge. Can be edited or deleted before activation.

Error Scenarios

E1 - Invalid Weight Total: If criteria weights don't sum to 100%, form shows red error: "Total weight is 95%. Please adjust criteria to reach 100%." Submit button is disabled.
E2 - Negative Score Impact: If officer enters negative scoring (e.g., -2 to 5), system warns: "Negative scores may distort pay gap analysis. Consider using 1-5 scale." Shows confirmation dialog to proceed.
E3 - Permission Denied: If user lacks Compliance Officer role, form is read-only with gray overlay and message: "You do not have permission to modify job evaluation methodology. Contact your HR Administrator."

Acceptance Criteria

Functional Requirements

  • System displays job evaluation form with 7 default criteria and weight fields
  • Real-time validation prevents activation if weights don't total 100%
  • Officer can customize weights and save either as draft or activate immediately
  • Activation applies new methodology to all subsequent job evaluations
  • System prevents unauthorized access (non-Compliance Officers see read-only view)

Compliance & Security Requirements

  • Every methodology change logged to immutable audit trail with timestamp and user ID
  • Audit log entries include full change details (before/after weights, approver)
  • User ID stored pseudonymized (SHA-256 hash) in audit log
  • System records which jobs use which methodology version for traceability
  • Email notification sent to all Compliance Officers when methodology activated
🔒 Directive 2023/970 Compliance: Article 4 requires job evaluation based on objective criteria. This use case ensures methodology is documented, applied consistently, and auditable. Pseudonymized audit logging satisfies GDPR Article 25 (data protection by design).

Data Entities Involved

Entity Field Storage/Protection
JobEvaluationCriteria criteriaId, name, weight, description, scoringScale Unencrypted (non-personal data)
EvaluationMethodology methodologyId, version, criteria[], status, activatedAt, activatedBy activatedBy field pseudonymized (SHA-256)
AuditLog logId, timestamp, userId, action, changeDetails, ipAddress Immutable append-only, userId pseudonymized, encrypted at rest

📊UC2: Salary Data Introduction & Pseudonymization

Actor(s) HR Specialist, Data Manager
Trigger Initial data load or monthly payroll sync
Duration 30-60 minutes (depending on dataset size)
Directive Reference Art. 5 (Data Minimization), GDPR Art. 32 (Encryption)

Narrative Description

HR Specialist imports employee salary data into the system. The system applies pseudonymization at import time, converting direct identifiers (names, employee IDs) into irreversible hashes. This ensures salary data is analyzed without personally identifying individuals, satisfying GDPR requirements for data minimization.

Pre-conditions

  • User has "HR Specialist" or "Data Manager" role with Employee Management permissions
  • Job evaluation methodology is already activated (UC1 completed)
  • CSV/Excel file with employee data is available (columns: EmployeeID, FirstName, LastName, Department, JobTitle, GrossSalary, Gender, StartDate)
  • System is configured with pseudonymization algorithm (SHA-256 hashing)

Main Flow

1
Access Bulk Import Interface
HR Specialist navigates to Employee Management → Bulk Import. System displays upload interface with guidance: "Upload CSV or Excel file containing employee salary data. Data will be pseudonymized on import."
2
Select and Upload File
Specialist clicks "Choose File", selects employees_2024.csv (2,341 records). System displays file preview: "2,341 employees detected. Columns: EmployeeID, FirstName, LastName, Department, JobTitle, GrossSalary, Gender, StartDate"
3
Configure Column Mapping
System auto-detects column structure. Specialist reviews mapping:
EmployeeID → Pseudonymization Key FirstName, LastName → Discard (not needed after pseudonymization) Department → Keep (for gap analysis by department) JobTitle → Keep (for job evaluation link) GrossSalary → Keep (core data for analysis) Gender → Keep (protected characteristic for gap analysis) StartDate → Keep (tenure analysis)
Specialist confirms or adjusts mapping. System validates "FirstName and LastName will be permanently discarded during import. Proceed?"
4
Data Quality Validation
System performs validation scan:
• 3 records have missing GrossSalary (rows 421, 892, 1,756) → Highlighted as errors • 12 records have invalid Gender values ("M/F/Other" expected, found "Male/Female") → Warnings • 0 records have duplicate EmployeeID → OK
Specialist is prompted: "Found 3 errors and 12 warnings. Import will fail for error rows. Fix data and re-upload or continue with 2,338 valid records?"
Decision Point: Continue with 2,338 records or halt import to fix source data?
5A
[If Continuing] Confirm Pseudonymization
Specialist reviews pseudonymization confirmation:
"⚠️ WARNING: The following data will be PERMANENTLY REMOVED during import: • FirstName (1st identifier) • LastName (2nd identifier) • EmployeeID (original employee ID) Only the pseudonymized hash will be stored. You will not be able to reverse-engineer employee identities from the imported data. Reason: GDPR Article 4 - Pseudonymization ensures salary data cannot be linked to identified individuals during gap analysis."
Specialist must click "I understand - proceed with pseudonymization" to continue.
5B
[If Fixing Data] Export Error Report
Specialist clicks "Download Error Report". System generates CSV with flagged rows and reasons. Specialist fixes source data in HR system (Workday, SAP) and re-uploads.
6
Execute Pseudonymization Import
System processes 2,338 records through pseudonymization pipeline:
For each employee record: 1. Hash = SHA-256(EmployeeID + "salt123") 2. Create: Employee_Pseudonymized { hash: "a4b5c6d7...", department: "Engineering", jobTitle: "Senior Developer", grossSalary: 85000, gender: "M", startDate: "2020-03-15" } 3. Original EmployeeID and names DELETED 4. Store encrypted in database
Status bar shows: "Processing 2,338 records... 45% complete. Est. 2 minutes remaining."
7
Verify Import Completion
Import completes. System displays:
✓ Import Successful • 2,338 employee records pseudonymized and imported • 3 records failed (missing salary data) • Pseudonymized data linked to 1,456 evaluated jobs • 882 employees lack job evaluations (warning: these cannot be included in gap analysis)
8
Audit Logging & Reporting
System records:
AuditLog Entry: - Timestamp: 2024-05-13 10:45:22 UTC - UserId: - Action: "BULK_IMPORT_EMPLOYEES" - RecordsProcessed: 2338 - RecordsFailed: 3 - PseudonymizationAlgorithm: "SHA-256" - DataRetention: "Salary data retained for 3 years per EU regulations" - Status: "COMPLETED"
Specialist receives email: "Bulk import completed. 2,338 employees now pseudonymized in system. Next step: Run salary gap analysis or evaluate remaining 882 employees."
✓ Success Outcome: Salary data is now pseudonymized and ready for gap analysis. Identifiable information has been permanently removed. System maintains encrypted connection between pseudonymous records and job evaluations for analysis purposes.

Alternative Flows

A1
Monthly Salary Update (Incremental)
For monthly updates, Specialist uploads only changed/new records (e.g., 48 new employees, 312 salary changes). System matches pseudonymous records: if EmployeeID "E1234" was previously imported as hash "a4b5c6d7...", it updates the existing pseudonymous record with new salary. No duplicate hashes created.
A2
Re-import with Updated Salary Data
Specialist clicks "Replace All Employee Data". System displays warning: "This will delete all 2,338 existing pseudonymized records and re-import. Any gap analysis reports based on old data will become invalid. Proceed?" This allows complete refresh without manual deletion.

Error Scenarios

E1 - Invalid File Format: If specialist uploads .txt or unsupported format, system shows: "File format not supported. Please upload .csv or .xlsx file."
E2 - Missing Required Columns: If file lacks GrossSalary column, import fails with: "Required column 'GrossSalary' not found. Cannot calculate pay gaps without salary data."
E3 - Encryption Failure: If pseudonymization process fails (e.g., disk full), system rolls back: "Pseudonymization failed at record 1,245. Imported 1,244 records only. Check disk space and retry."
E4 - Permission Denied: If user lacks Employee Management permission, system blocks upload: "You do not have permission to import salary data. Contact your HR Administrator."

Acceptance Criteria

Functional Requirements

  • System accepts CSV and Excel files with employee salary data
  • Column mapping interface allows flexible data structure configuration
  • Data quality validation detects missing or invalid values before import
  • Pseudonymization removes identifiable information (EmployeeID, FirstName, LastName) irreversibly
  • Pseudonymized records maintain link to job evaluations for analysis
  • Import status clearly shows records processed, failed, and warnings

Compliance & Security Requirements

  • SHA-256 hashing applied with consistent salt for pseudonymization
  • Original EmployeeID and names PERMANENTLY deleted (not reversible)
  • Pseudonymized data encrypted at rest using AES-256
  • Bulk import logged to immutable audit trail with record counts and user pseudonym
  • System confirms pseudonymization warning before proceeding
  • Audit trail maintains data retention policy (3 years per EU regulations)
🔒 GDPR & Directive 2023/970 Compliance: Pseudonymization (Article 4 GDPR) ensures salary data cannot identify individuals. Combined with role-based access controls, this satisfies Article 5 (data minimization) and Article 32 (encryption). Deletion of identifiable information removes individuals from direct salary analysis while maintaining aggregate gap analysis capability.

📈UC3: Salary Transparency Analysis & Pay Gap Calculation

Actor(s) HR Specialist, Compliance Officer, Manager
Trigger Quarterly review or on-demand analysis
Duration 5-15 minutes (automated calculation)
Directive Reference Art. 7 (Pay Gap Calculation), Art. 8 (Data Disclosure)

Narrative Description

HR Specialist initiates automated salary gap analysis. System calculates gender-based and protected characteristic-based salary gaps using pseudonymized data. Results are presented in standardized format with transparent methodology. Gaps exceeding threshold require justification entry (UC4). Drill-down capability allows analysis by department, job level, and tenure.

Pre-conditions

  • Salary data has been imported and pseudonymized (UC2 completed)
  • Job evaluations are complete for at least 80% of employees
  • User has "HR Specialist" or "Compliance Officer" role
  • System has minimum 100 employees (threshold for statistical validity)

Main Flow

1
Access Gap Analysis Module
HR Specialist navigates to Analysis → Pay Gap Analysis. System displays dashboard overview: "Latest analysis: 2024-04-30. Organization: 2,338 employees, 1,456 evaluated jobs. Next mandatory report due: 2024-12-31."
2
Configure Analysis Parameters
Specialist selects analysis scope:
Time Period: Last 12 months (auto-populated) Scope: Organization-wide (default) OR by Department Grouping: Overall + By Gender (required by Directive) Including: Active employees only (exclude UNPAID_LEAVE, TERMINATED) Minimum Group Size: 10 (statistical validity threshold)
Specialist can adjust parameters. System validates minimum employee count in each group.
Decision Point: Run organization-wide analysis or analyze by department?
3
Execute Gap Calculation Algorithm
System processes pseudonymized salary data through gap calculation engine:
Algorithm: ((avg_salary_male - avg_salary_female) / avg_salary_female) × 100 Step 1: Group pseudonymized employees by gender - Male: 1,234 employees, avg salary €58,400 - Female: 1,104 employees, avg salary €54,200 Step 2: Control for job evaluation scores - Male avg job score: 68.5 points - Female avg job score: 67.8 points - Confidence: Difference is statistically insignificant (p > 0.05) Step 3: Calculate raw gap Gap = ((58,400 - 54,200) / 54,200) × 100 = 7.75% Step 4: Flag for analysis Raw gap: 7.75% (exceeds 5% threshold → Requires justification)
Status: "Calculating gaps... Processing 2,338 employee records. ~20 seconds."
4
Display Results Dashboard
System presents comprehensive analysis results:
✓ ANALYSIS COMPLETE - Organization-Wide Pay Gap (12-month period) Overall Gender Gap: 7.75% (REQUIRES JUSTIFICATION) • Methodology: Raw average salary comparison by gender • Methodology: Adjusted for job evaluation scores (controls for role complexity) Unadjusted Gap: 7.75% favor males Adjusted Gap: 3.2% favor males (controls for job evaluation differences) Group Distribution: • Female employees: 1,104 (47%) • Male employees: 1,234 (53%) Statistical Significance: p-value = 0.018 (significant at 95% confidence) Recommendation: Gap is statistically significant and above 5% threshold. Justification required per Article 5.
5
Drill-Down Analysis by Department
Specialist clicks "View by Department" to analyze underlying causes. System displays department-level breakdown:
Department Female Avg Male Avg Gap % Status
Engineering €62,500 €65,800 5.3% ⚠️ Requires Justification
HR & Admin €38,200 €37,900 -0.8% ✓ No Gap
Sales €48,300 €52,100 7.8% ⚠️ Significant Gap
Specialist can drill into Engineering dept: Engineering > Job Title > Seniority level for root cause analysis.
6
Export Analysis Report
Specialist clicks "Export Report". System generates PDF with: Executive Summary, Methodology Explanation, Detailed Gap Calculations, Department Breakdown, Statistical Analysis, Chart Visualizations, Compliance Statement. Report is marked: "CONFIDENTIAL - Internal Use Only" with watermark.
7 7
Flag Gaps for Justification Workflow
System identifies gaps ≥5% and automatically creates justification tasks:
Justification Task 1: Engineering Department (5.3% gap) Justification Task 2: Sales Department (7.8% gap) These tasks are assigned to Department Managers and Compliance Officer for root cause analysis and corrective action planning (triggers UC4).
8
Audit Logging & Traceability
System records analysis to immutable audit trail:
AuditLog Entry: - Timestamp: 2024-05-13 14:22:00 UTC - UserId: - Action: "PAY_GAP_ANALYSIS_EXECUTED" - EmployeeCount: 2338 - OverallGap: 7.75% - DepartmentsAnalyzed: 8 - JustificationsCreated: 2 - Algorithm: "Raw + Adjusted for Job Evaluation" - Status: "COMPLETED"
✓ Success Outcome: Salary gap analysis complete. Organization-wide and departmental gaps identified. Gaps ≥5% flagged for justification. Results exported as PDF report. Audit trail documents analysis parameters and findings.

Alternative Flows

A1
Single Department Analysis
Specialist selects "Engineering" department only. System calculates gap for 234 Engineering employees (156 male, 78 female). Displays department-specific results without organization-wide aggregate.
A2
Historical Trend Analysis
Specialist clicks "View Trends". System displays pay gap by quarter over past 24 months. Chart shows: Q1 2023: 8.2%, Q2 2023: 7.9%, ..., Q1 2024: 7.75%. Specialist can assess progress toward pay equity goals.

Error Scenarios

E1 - Insufficient Data: If fewer than 100 employees or < 30% job evaluation coverage, system displays: "Cannot calculate reliable pay gap. Minimum 100 employees required. Currently 67 employees with complete data."
E2 - Small Group Size Warning: If a department has fewer than 10 employees, system warns: "Department 'Corporate Governance' has 8 employees (below 10-person minimum). Gap calculation omitted to protect statistical integrity. Consider analyzing with nearby periods."
E3 - Missing Job Evaluations: If 400 employees lack job evaluations, system warns: "822 employees (35%) lack job evaluations. Adjusted gap calculation unavailable. Unadjusted gap shown. Evaluate remaining employees for full analysis."

Acceptance Criteria

Functional Requirements

  • System calculates gender-based pay gap using standardized formula
  • Results display both raw and job-evaluation-adjusted gaps
  • Dashboard shows department-level and organization-wide analysis
  • Drill-down capability allows granular analysis (department → job → seniority)
  • System flags gaps ≥5% for justification workflow
  • Export functionality generates PDF reports with methodology and results

Compliance & Security Requirements

  • Gap calculation performed on pseudonymized data only (never on identified employees)
  • Analysis logged to audit trail with timestamp, user, parameters, and results
  • Statistical validity checks enforce minimum group sizes (10 employees)
  • Reports marked "CONFIDENTIAL" and watermarked
  • Results compared to prior analyses for trend tracking
  • Directive Article 7 methodology documented in methodology section of exported report
🔒 Directive 2023/970 Compliance: Article 7 mandates pay gap calculation. This use case implements required methodology: comparison of average salary by gender, with statistical significance testing. Pseudonymized data analysis satisfies GDPR while enabling gap identification. Audit logging provides traceability required by Article 8 (Data Disclosure).

✅UC4: Corrective Measures & Justification Workflow

Actor(s) Manager, HR Specialist, Compliance Officer
Trigger Pay gap analysis identifies gap ≥5%
Duration 3-7 days (approval workflow)
Directive Reference Art. 5 (Justification for Gaps)

Narrative Description

When salary gap analysis reveals gaps ≥5%, the system creates justification tasks. Department Manager documents root causes and proposes corrective measures (e.g., salary adjustments, hiring strategy changes, job evaluation recalibration). HR Specialist reviews and Compliance Officer approves. Documentation becomes evidence for regulatory compliance.

Pre-conditions

  • Pay gap analysis completed, gap ≥5% identified (UC3 completed)
  • Justification task automatically created by system
  • Manager has access to pseudonymized gap data by job level and tenure
  • System configured with justification template and approval workflows

Main Flow

Phase 1: Detection
Phase 2: Justification
Phase 3: Approval
Phase 4: Implementation
1
Manager Receives Justification Task
System automatically creates task: "Pay Gap Detected: Engineering Department (5.3% gap)". Manager receives email notification: "A significant pay gap has been detected in your department. Please document the reason and propose corrective measures within 5 business days."
2
Access Justification Form & Gap Context
Manager logs in and navigates to Compliance → Justifications → Engineering Gap Task. System displays:
Gap Context (Pseudonymized): - Overall Engineering Gap: 5.3% (female €62,500 avg, male €65,800 avg) - By Job Level: • Senior Engineers (n=45): 6.8% gap • Mid-Level Engineers (n=89): 4.2% gap • Junior Engineers (n=100): 1.1% gap (no gap) - By Tenure: • 5+ years: 7.1% gap • 2-5 years: 3.8% gap • <2 years: 0.9% gap (no gap)
Analysis shows gap is concentrated among Senior Engineers with 5+ years tenure.
3
Manager Documents Root Cause Analysis
Manager fills justification form with root cause analysis:
Root Causes Identified: 1. Historical Hiring Imbalance (40% of gap explained) "Senior engineering cohort (5+ years) was recruited during 2018-2019 when tech industry had fewer female candidates. Senior female engineers represent only 22% of cohort vs. 40% in current hiring." 2. Promotion Timing Differences (35% of gap) "Male senior engineers promoted ~1.5 years earlier on average. 3 recent female engineers reached senior level in 2023-2024; salaries will reach parity in next review cycle." 3. Market Salary Variation (25% of gap) "Senior engineers with AI/ML specialization (predominantly male in cohort) command 8-12% premium. We adjusted comp in 2024 to attract female AI specialists."
4
Propose Corrective Measures
Manager enters corrective action plan:
Corrective Measures Proposed: Immediate (Q2 2024): - Conduct salary review for 3 female senior engineers with 5+ years tenure - Target: Bring salaries to within 2% of peer males with same job eval score - Estimated cost: €8,500/year - Responsibility: HR Specialist (with Compliance approval) - Timeline: Complete by June 30, 2024 Short-term (Q3-Q4 2024): - Revise senior engineer hiring strategy to increase female candidate pipeline - Set goal: 45% female senior hires in 2024 (up from 22% historical) - Responsibility: Recruiting Manager - Timeline: Implement job postings August 2024 Medium-term (2025): - Establish mentorship program for mid-level female engineers - Track promotion timing parity - Goal: Eliminate 2-3 year promotion gap - Responsibility: Engineering Leadership - Timeline: Program launch February 2025
5
Manager Submission & HR Review
Manager clicks "Submit for Review". System changes status to "Pending HR Review". HR Specialist receives notification: "Justification submitted for Engineering 5.3% gap. Review and assess corrective measures feasibility." HR Specialist reviews proposal and validates:
✓ Root cause analysis is thorough and evidence-based ✓ Proposed salary adjustment (€8,500) is approved in budget ⚠️ Hiring goal (45% female) may be ambitious; recommend 40% interim target ✓ Mentorship program aligns with broader DEI initiatives
HR Specialist can approve with recommendations or request revisions from Manager.
6
Compliance Officer Final Approval
HR Specialist forwards to Compliance Officer with recommendation: "Approve with modifications to hiring target (40% instead of 45%)." Compliance Officer reviews for regulatory compliance:
✓ Justification adequately explains 5.3% gap ✓ Corrective measures are concrete and time-bound ✓ Plan includes salary equity adjustment (immediate mitigation) ✓ Long-term measures address systemic causes (hiring, promotion parity) ✓ Plan is documented and auditable COMPLIANCE FINDING: Gap justification satisfies Article 5 requirements. If measures are implemented as proposed, organization demonstrates good-faith effort to eliminate unjustified gender pay gap.
Compliance Officer clicks "Approve". System records approval decision.
7
Implementation & Monitoring
Once approved, system creates implementation tasks:
✓ JUSTIFICATION APPROVED Implementation Tasks Created: 1. [Q2 2024] Salary review for 3 female senior engineers (Assigned to: HR Specialist) 2. [Q3 2024] Implement revised senior engineer hiring strategy (Assigned to: Recruiting) 3. [Q4 2024] Launch mentorship program (Assigned to: Engineering Leadership) Next Gap Analysis: November 2024 (will reassess whether corrective measures reduced gap)
System sets reminder: "Q3 2024: Review progress on corrective measures. Have hiring targets been met? Are salary adjustments in place?"
8 8
Audit Logging & Documentation
System records complete justification workflow to audit trail:
AuditLog Entries: - [2024-05-13 10:00] Justification task created (Gap 5.3% detected in Engineering) - [2024-05-15 14:30] Justification submitted by Manager (root causes + corrective measures) - [2024-05-16 09:45] HR Review completed (approved with recommendations) - [2024-05-17 11:20] Compliance Officer approved justification - [2024-05-17 11:21] Implementation tasks created Documentation includes: - Original gap analysis and context data - Manager's root cause analysis - Corrective measure proposal with timeline - All reviewer comments and approvals - Implementation task assignments
This creates evidence trail demonstrating organization's compliance efforts for potential regulatory review.
✓ Success Outcome: Gap justification documented and approved. Corrective measures assigned to responsible parties with deadlines. Implementation tracked. Documentation available for regulatory audit (Article 5 compliance evidence).

Alternative Flows

A1
Justification Rejected by HR or Compliance
If HR Specialist finds justification insufficient ("Root cause analysis does not adequately explain gap. Please provide additional detail on promotion timeline differences."), Manager is notified. System returns task to "In Progress" with comments. Manager has 5 days to revise and resubmit.
A2
Objectively Unjustified Gap
If Manager cannot adequately justify gap (e.g., "No explanation provided") or Compliance Officer determines gap is unjustified, system flags for escalation: "OBJECTIVELY UNJUSTIFIED GAP: Corrective salary adjustment is MANDATORY within 90 days. Escalated to CFO and Compliance Officer for immediate action."

Error Scenarios

E1 - Insufficient Justification: If Manager provides only 1-2 sentences, system warns: "Justification appears incomplete. Please provide detailed analysis of root causes (minimum 100 words recommended)."
E2 - Missing Corrective Measures: If Manager fails to propose corrective measures, system blocks submission: "Corrective measures must be specified. Article 5 requires explanation of gap AND action plan to address it."
E3 - Approval Timeout: If justification is not approved/rejected within 10 days, system escalates to Compliance Officer with reminder: "Justification for Engineering gap pending approval for 10 days. Please review and render decision."

Acceptance Criteria

Functional Requirements

  • System automatically creates justification task when gap ≥5% detected
  • Manager can access gap context (pseudonymized drill-down by job level/tenure)
  • Justification form allows detailed root cause documentation
  • Manager proposes concrete corrective measures with timelines
  • Multi-stage approval workflow (HR review → Compliance approval)
  • Approved measures converted to implementation tasks with assignments

Compliance & Security Requirements

  • Gap analysis context available to Manager (role-based access)
  • Complete workflow logged to immutable audit trail
  • All comments, approvals, and revisions recorded with timestamp
  • Implementation tasks tracked and monitored until completion
  • Justification documentation available for regulatory audit
  • Non-compliance (unjustified gap) escalated automatically to CFO/Compliance
🔒 Directive 2023/970 Compliance: Article 5 requires employers to justify any gender pay gap ≥ 5% and implement corrective measures. This use case documents the justification process and creates auditable evidence of compliance efforts. Rejection of inadequate justifications and escalation of unjustified gaps ensures organization cannot ignore identified disparities.

👤UC5: Employee Salary Transparency Requests (Article 10)

Actor(s) Employee, HR Specialist
Trigger Employee initiates transparency request
Duration 15 days (legal response time)
Directive Reference Art. 10 (Right to Information)

Narrative Description

Directive 2023/970 grants employees the right to request information about salary distribution and comparison with colleagues in the same job. The system enables self-service transparency requests while protecting privacy through pseudonymization. HR Specialist processes requests and provides comparative data within 15-day legal deadline.

Pre-conditions

  • Employee is logged into system with verified identity
  • Employee is an active employee in pseudonymized salary dataset
  • System has minimum 3 other employees in same job title for meaningful comparison
  • HR Specialist has processed employee record

Main Flow

1
Employee Initiates Request
Employee navigates to Self-Service → Salary Transparency Request. System displays: "You have the right under EU Directive 2023/970 to receive information about salary ranges for your job title. This request will be processed within 15 days."
2
Employee Submits Request
Employee fills request form:
Request Details: - Employee confirms current job title: "Senior Software Engineer" - Employee selects comparison criteria: ☑ Show salary distribution for same job title (required) ☑ Show breakdown by gender (optional) ☑ Show breakdown by experience level (optional) ☐ Show individual colleague salaries (NOT available - privacy protected) Employee clicks "Submit Request" System confirms: "Your request has been submitted. You will receive response within 15 business days."
3
System Validates Employee Eligibility
System checks: Is employee "Senior Software Engineer" in database? Are there ≥3 other Senior Software Engineers for meaningful comparison? System finds: 23 other Senior Software Engineers (15 male, 8 female). Eligibility confirmed. Request routed to HR Specialist queue.
4
HR Specialist Processes Request
HR Specialist receives task: "Salary Transparency Request from Employee [pseudonym]. Job: Senior Software Engineer. Due: 2024-05-28." Specialist navigates to request and system displays:
Employee Transparency Request Requesting Employee Salary Data (Pseudonymized): - Job Title: Senior Software Engineer - Salary: €72,500 - Gender: Female - Tenure: 4 years - Job Eval Score: 74 points Peer Comparison Group (All Senior Software Engineers): - Total in role: 24 employees (including requesting employee) - Comparison window: Same department, same job evaluation band
5
Generate Transparency Response
HR Specialist clicks "Generate Response". System creates personalized transparency report:

Error Scenarios

E1 - Insufficient Peer Group: If employee works in niche role with only 2 other people, system blocks request: "Cannot provide meaningful comparison (only 3 people in role). Transparency report would not provide statistical validity. Contact HR directly for individual salary review."
E2 - Non-Active Employee: If employee is on unpaid leave or contract has ended, system shows: "Transparency reports are available to active employees only. If you were recently separated, contact HR with your request."
E3 - Request Exceeds 15-Day Deadline: If HR Specialist has not processed request by day 12, system sends reminder: "Transparency request due in 3 days. Please generate and deliver response to maintain compliance."

Acceptance Criteria

Functional Requirements

  • Employee can self-initiate transparency request through self-service portal
  • System validates employee is active and has peer group for comparison
  • System auto-generates personalized salary comparison report
  • Report shows salary distribution, gender breakdown, contextual factors
  • Report does NOT disclose individual colleague names or salaries
  • HR Specialist reviews and approves before delivery
  • Employee receives response within 15 business days

Compliance & Security Requirements

  • All data in response is pseudonymized (no colleague identification)
  • Request and response logged to immutable audit trail with timestamps
  • Processing time tracked and monitored against 15-day legal deadline
  • Response includes appropriate contextual explanations (job eval, tenure factors)
  • System prevents over-disclosure (cannot request individual colleague salaries)
  • Employee has right to follow-up salary review request based on transparency response
🔒 Directive 2023/970 Compliance: Article 10 grants employees right to information about salary distribution. This use case implements self-service transparency requests with 15-day response deadline (Art. 10.1). Pseudonymization protects colleague privacy while enabling meaningful comparison. Audit logging provides evidence of compliance with disclosure obligations.
