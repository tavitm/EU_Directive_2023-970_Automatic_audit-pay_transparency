Mapping Principles

1. Pseudonymization-First: All employee identifiers converted to irreversible hashes at import. Original names/IDs permanently deleted.
2. Directive Article Traceability: Each system entity tagged with source Directive article(s) for regulatory audit.
3. Immutable Audit Trail: Every data change logged with user pseudonym, timestamp, old/new values. Append-only log.
4. Encryption at Rest: All personal/pseudonymized data encrypted with AES-256. Keys managed in hardware security module (HSM).
5. Role-Based Access: Data access controlled by job role. Employees see only own data. Managers see departmental aggregates. Compliance Officers see full scope.

Transformation: Import Process

Step 1: Raw HR Data (Identifiable)
EmployeeID="E12345", FirstName="Maria", LastName="Rossi", Salary=€72,500, Gender="F"

Step 2: Pseudonymization
Hash = SHA-256("E12345" + "salt123") = "a4b5c6d7e8f9..."

Step 3: Delete Identifiers
Original EmployeeID, FirstName, LastName DELETED (not reversible)

Step 4: Store Pseudonymized
EmployeePseudonymous {
  pseudonymHash: "a4b5c6d7e8f9...",
  gender: "F",
  jobTitle: "Senior Developer",
  salary: €72,500
}

Result: Data analyzable for gaps, but cannot identify individuals.

📈Gap Analysis Entities

Source: Directive 2023/970, Article 7

Article 7 (Pay Gap Calculation): "Member States shall establish the manner in which employers calculate the gender pay gap. The calculation shall be based on the comparison of the average gross hourly wage of male and female workers."

Entity: PayGapAnalysis

Source Document
Article 7: "calculation of gender pay gap based on comparison of average gross hourly wage" Requirement: Standardized calculation method, parameters documented, result auditable
System Entity
PayGapAnalysis { analysisId: UUID analysisDate: DateTime scope: String ("ORGANIZATION", "DEPARTMENT", "JOB_TITLE") scopeValue: String (dept name or job) timePeriod: String ("2024-01 to 2024-12") parameters: { employeeFilter: "ACTIVE_ONLY", minGroupSize: 10, jobEvalAdjustment: true } results: { totalEmployees: 2338, females: { count: 1104, avgSalary: 54200 }, males: { count: 1234, avgSalary: 58400 }, rawGap: 7.75, adjustedGap: 3.2, pValue: 0.018 } statisticalValidity: true directiveArticles: ["7"] executedBy: String (pseudonymized) auditTrail: AuditLog[] }

Gap Calculation Formula

Raw Gap = ((AvgSalary_Male - AvgSalary_Female) / AvgSalary_Female) × 100 Example: AvgSalary_Male = €58,400 AvgSalary_Female = €54,200 Gap = ((58,400 - 54,200) / 54,200) × 100 = (4,200 / 54,200) × 100 = 0.0775 × 100 = 7.75% (gap favors males) Adjusted Gap (controlling for job evaluation): Adjusts for job evaluation score differences between genders If males have average score 68.5 and females 67.8, adjustment factor accounts for this 0.7 point difference.

Entity: GapResult

Source Document
Article 7: "results of the pay gap calculation" Article 5: "any gap...shall be justified" Requirement: Results stored with compliance status (gap ≥5% requires justification)
System Entity
GapResult { gapResultId: UUID analysisId: UUID (FK to PayGapAnalysis) dimension: String ("OVERALL", "BY_DEPARTMENT", "BY_JOB_TITLE", "BY_TENURE", "BY_SENIORITY") dimensionValue: String gapPercentage: Decimal gapDirection: Enum ("MALE_ADVANTAGE", "FEMALE_ADVANTAGE", "NO_GAP") requiresJustification: Boolean (true if ≥5%) justificationId: UUID (FK if applicable) complianceStatus: Enum ("COMPLIANT", "UNJUSTIFIED", "JUSTIFIED", "PENDING") directiveArticles: ["7", "5"] statisticalPValue: Decimal minorityCount: Integer (smaller group size) }

⚖️Business Rules & Compliance Constraints

Rule 1: Minimum Group Size for Gap Analysis

Source: GDPR Article 5(1)(a) - Data minimization; Statistical validity requirement
Rule: Gender-based gap calculation requires minimum 10 employees in each gender group to ensure statistical validity and prevent disclosure of small group data.

Implementation: PayGapAnalysis.parameters.minGroupSize = 10
Validation: If female count < 10 OR male count < 10, gap calculation blocked with message: "Insufficient group size for statistical validity (need 10+, have X)."

Rule 2: Pseudonymization is Irreversible

Source: GDPR Article 4(11) - Pseudonymisation definition requires no re-identification possible
Rule: Original EmployeeID and names must be permanently deleted at import time. No reversibility possible.

Implementation: EmployeePseudonymous.pseudonymHash = SHA-256(EmployeeID + salt)
Validation: Import process deletes original identifiers before saving. Audit log records deletion count. Cannot re-run import to recover.

Rule 3: Gap ≥5% Requires Justification

Source: Directive Article 5 - "any gap...shall be justified"
Rule: Any GapResult with gapPercentage ≥ 5.0 automatically triggers justification workflow.

Implementation: GapResult.requiresJustification = (gapPercentage >= 5.0)
Enforcement: System creates GapJustification task immediately. Task assigned to Department Manager. 5-day response deadline.
Escalation: If no response after 5 days, Compliance Officer notified. If gap remains unjustified, marked "NON_COMPLIANT" and escalated to CFO.

Rule 4: Justification Requires Corrective Measures

Source: Directive Article 5 - "take...corrective measures"
Rule: GapJustification cannot be submitted without at least one CorrectiveMeasure with timeline and responsible party.

Implementation: Form validation requires correctiveMeasures[].length > 0
Validation: System blocks submission with message: "You must propose at least one corrective measure."

Rule 5: Compliance Officer Final Approval

Source: Directive Article 9 - Verification and documentation for regulatory review
Rule: GapJustification requires 2-step approval: HR Specialist review + Compliance Officer approval. HR cannot approve on behalf of Compliance.

Implementation: GapJustification.status workflow:
DRAFT → SUBMITTED → HR_REVIEW → COMPLIANCE_REVIEW → APPROVED

Enforcement: HR Specialist can request revisions but only Compliance Officer can approve. Role-based access control enforced.

Rule 6: Audit Trail is Immutable & Append-Only

Source: GDPR Article 32 & Directive Article 9 - Audit for verification
Rule: AuditLog records cannot be modified, deleted, or overwritten. Only append allowed.

Implementation: AuditLog table configured as immutable (database constraint):
- No UPDATE operations allowed on logId
- No DELETE operations allowed on logId
- Only INSERT allowed

Storage: Append-only ledger (e.g., event store). Each entry references previous entry hash for tamper detection.

Rule 7: Transparency Request Must Be Answered Within 15 Days

Source: Directive Article 10(2) - "shall provide...within 15 calendar days"
Rule: Employee transparency requests must receive response within 15 calendar days of submission.

Implementation: System tracks requestSubmittedAt and sets dueDate = requestSubmittedAt + 15 days
Enforcement: If not completed by day 12, HR Specialist receives reminder. If not completed by day 15, system alerts Compliance Officer. System logs any late responses as non-compliance.

Rule 8: Role-Based Data Access Control

Source: GDPR Article 5(1)(f) - Data security; Principle of least privilege
Rule: Data visibility depends on user role:

Employee: Can see own salary data, peer salary distribution (anonymized), transparency report
Manager: Can see department data, gap analysis for their dept, proposing justifications
HR Specialist: Can see all employee data (pseudonymized), process imports, approve justifications
Compliance Officer: Can see everything, final approval authority
CFO: Can see financial impact of corrective measures, escalation alerts

Implementation: Row-level security + role-based column access. Queries filtered by role at database level.

Rule 9: Data Encryption At Rest & In Transit

Source: GDPR Article 32 - "encryption...of personal data"
Rule: All personal/pseudonymized data encrypted with AES-256 at rest. All API communication via TLS 1.3.

Implementation:
- EmployeeSalary: AES-256 encrypted in database
- EmployeePseudonymous: AES-256 encrypted in database
- AuditLog: AES-256 encrypted
- Encryption keys: Stored in HSM, rotated quarterly
- API: TLS 1.3, certificate pinning for mobile clients

Rule 10: Data Retention & Secure Deletion

Source: GDPR Article 5(1)(e) - Storage limitation; Directive: 3-year retention
Rule: Salary and gap analysis data retained for 3 years from end of relevant period. Automatically deleted after 3 years using secure deletion (overwrite + crypto erase).

Implementation: DataRetentionPolicy defines retention for each data type:
- EmployeeSalary (period): Delete 3 years after period end
- PayGapAnalysis: Delete 3 years after analysis date
- AuditLog: Retain indefinitely (legal requirement)

Enforcement: Scheduled batch job checks deletion dates daily. Executes secure deletion (overwrite + crypto erase). Records deletion in AuditLog with crypto hash receipt.
