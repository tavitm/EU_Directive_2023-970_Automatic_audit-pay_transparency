TS-M1-001 Creare Nou Post - Happy Path

Preconditions

  • Utilizator: HR Specialist
  • Role: Full access jobs
  • Status: Logged in

Steps

  • Navigate to "Gestionare Posturi"
  • Click "Nou Post" button
  • Fill form: Job Code (unique), Title, Dept
  • Set Manager (dropdown)
  • Set Level (1-5)
  • Click "Salvează"
✓ Post creat cu ID unic generat | ✓ Salvat în DB | ✓ Audit log entry creată | ✓ Mesaj succes afișat

Acceptance Criteria (AC)

  • AC1: Job Code MUST be unique (no duplicates allowed)
  • AC2: Required fields: Job Title, Department, Manager, Level
  • AC3: Job Code format: ^[A-Z0-9]{3,8}$ (alphanumeric, 3-8 chars)
  • AC4: System-generated job_id (UUID)
  • AC5: Audit log records: user_id, timestamp, action, job_id
  • AC6: Success notification displays "Post [JobCode] creat cu succes"

TS-M1-002 Evaluare Post pe 7 Criterii

Preconditions

  • Post creat (TS-M1-001)
  • Utilizator: Manager (post owner)
  • Sistem: Criterii preloaded (7)

Steps

  • View post details
  • Click "Evaluează" tab
  • Score each criterion (1-5)
  • Competencies: 4 points
  • Effort: 3 points
  • Responsibility: 5 points
  • Click "Calculează Scor"
✓ System calculates: (4×0.25 + 3×0.15 + 5×0.25 + ...) = 4.2 | ✓ Category auto-assigned: "High Value" | ✓ Results saved | ✓ HR notified

Acceptance Criteria (AC)

  • AC1: Each criterion has weight (percentages total 100%)
  • AC2: Score range: 1-5 (integers)
  • AC3: Weighted score = Σ(score × weight)
  • AC4: Final score rounded to 1 decimal place
  • AC5: Equal value category auto-assigned based on score range
  • AC6: Evaluation history versioned (timestamp, evaluator)
  • AC7: Cannot score same post twice (locked after approval)
Edge Case 1: What if scores are all 1? Score = 1.0 → Category = "Lowest" ✓
Edge Case 2: What if scores are all 5? Score = 5.0 → Category = "Highest" ✓
Edge Case 3: Decimal scores (e.g., 3.7)? System should round: 3.7 → Category based on range ✓

📊 M3: Analiza Diferențe Salariale

Modules: Salary Analysis, Pay Gap Calculation Actors: HR, Compliance Officer

TS-M3-001 Calculare GAP Salariu (Happy Path)

Preconditions

  • 500 employees with salary data
  • 50 posts evaluated
  • Data ready: balanced mix M/F
  • User: HR Analyst

Steps

  • Navigate to "Analiza GAP Salare"
  • Select: Category = "Mid-level"
  • Click "Calculează"
  • System processes all employees in category
  • Calculates: avg_salary(M), avg_salary(F)
  • Calculates: gap_percentage = ((M-F)/F)×100
✓ Category has 120 employees (70M, 50F) | ✓ M avg: 4000 | ✓ F avg: 3700 | ✓ Gap: 8.1% | ✓ Flag: ≥5% → "Needs justification"

Acceptance Criteria (AC)

  • AC1: Gap calculation: ((avg_M - avg_F) / avg_F) × 100
  • AC2: Gap rounded to 1 decimal place
  • AC3: Positive gap = Men earn more | Negative gap = Women earn more
  • AC4: Gap ≥ 5% flagged as "Requires justification"
  • AC5: Gap < 5% flagged as "No justification required"
  • AC6: Sample size shown (n=120, M=70, F=50)
  • AC7: Calculation date recorded (snapshot)
Edge Case 1: What if category has only 5 employees (3M, 2F)? Gap still calculated, but note "Small sample size" ✓
Edge Case 2: What if all employees are same gender (e.g., 100M, 0F)? System shows: "No female employees in category - cannot calculate gap" ✓

TS-M3-002 Drill-Down Analiza GAP pe Subcategorii

Preconditions

  • GAP calculated for "Mid-level": 8.1%
  • System has department breakdown
  • User: Compliance Officer

Steps

  • View analysis result: "Mid-level" 8.1% gap
  • Click "Detalii" / Drill-down
  • System shows breakdown by department:
  • - Engineering: 12% gap (20M, 15F)
  • - HR: 3% gap (5M, 20F)
  • - Sales: 9% gap (40M, 10F)
✓ Drill-down shows 3 departments | ✓ Engineering high gap (12%) identified | ✓ HR low gap (3%) identified | ✓ Sales gap (9%) identified

Acceptance Criteria (AC)

  • AC1: Drill-down available for all dimensions (category, dept, level, tenure)
  • AC2: Sub-category gap calculated same formula as parent
  • AC3: Sum of sub-category sample sizes = parent sample size
  • AC4: Each sub-result shows: count(M), count(F), avg_salary(M), avg_salary(F), gap%
  • AC5: Red highlight for gap ≥ 5% (visual flag)
  • AC6: Drill-down infinite (can go deeper: category → dept → team)

TS-SEC-003 Audit Logging: Immutable Trail

Preconditions

  • System running for 1 month
  • 1000s of actions logged
  • Audit log table: 50k rows

Steps

  • Test 1: Try to delete audit log entry → Fails (immutable)
  • Test 2: Try to UPDATE audit log → Fails (append-only)
  • Test 3: Verify all entries have timestamp + hash
  • Test 4: Check hash chain (each entry references previous)
  • Test 5: Tamper test → Change one entry → Hash chain breaks
✓ Delete blocked | ✓ Update blocked | ✓ Hash chain intact | ✓ Tamper detection works

Acceptance Criteria (AC)

  • AC2: Each entry: user_id, action, entity, timestamp, hash
  • AC3: Hash chain: entry_hash = hash(previous_hash + current_data)
  • AC4: Breaking hash chain triggers alert
  • AC5: Audit log backed up daily (separate storage)
  • AC6: Retention: 3 years minimum
  • AC7: Cannot modify even as superuser (database constraints)
GDPR Accountability & Article 5(1)(f): Immutable audit trail ensures integrity and non-repudiation ✓
